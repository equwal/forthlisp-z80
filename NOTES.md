# Z80 Forth/Lisp machine

A Scheme that runs on an emulated Z80 with 64 KiB of address space. Each layer
is built only from the layer below it.

```
 4. LISP     prelude.scm  (Scheme: lists, numbers, let/cond/case/do macros)
             lisp.fs      (Forth: heap, GC, reader, eval, printer, primitives)
                 | loaded as source text over the serial console by host.lisp
 3. FORTH    kernel.lisp  (our own indirect-threaded Forth: inner interpreter,
                           primitives, dictionary, outer interpreter, compiler,
                           serial console)
                 | assembled on the host
 2. SBCL     asm.lisp     (two-pass Z80 assembler hosted in SBCL)
                 | writes kernel.mos (Mostek header + bytes, loads at 0000)
 1. Z80      machine code, run by z80pack cpmsim
```

No third-party Forth is used. The Lisp is not generated by SBCL: SBCL only
sends `lisp.fs` and `prelude.scm` as text, line by line, and the Z80 Forth
compiles and evaluates them.

## Layer 2: why a small assembler, not sb-assem

SBCL's `sb-assem` (`define-instruction`, segments, emitters) is the right
model, and Paul Khuong's breadboard post uses it. But it is wired to the native
backend: instruction formats, registers (TNs), fixups and the disassembler all
belong to the x86-64 VOP machinery, and defining Z80 instructions there means
working inside `SB-VM` internals of one SBCL version. A Z80 needs about 70
encodings. `asm.lisp` keeps the breadboard style (instructions are Lisp data,
emitters write into a byte vector, Lisp functions act as VOP-like templates:
`code`, `colon`, `flag-code` in `kernel.lisp`) in 170 lines that do not depend
on SBCL internals.

Syntax: `(ld a (@ hl))`, `(ld (@ ix 3) b)`, `(jp nz loop)`, `(dw docol)`,
bare symbols are labels. `(@ x)` is indirection.

## Layer 3: the Forth kernel

- Indirect threaded. BC = IP, SP = data stack, IX = return stack.
- 51 primitives in assembly, 64 colon words threaded at build time by
  `compile-tokens` (control flow resolved like a Forth compiler would).
- Words: stack, memory, arithmetic (`um*`, `um/mod`, `d+`), comparisons,
  `key emit key?`, `cmove fill s=`, `: ; if else then begin while repeat until
  again recurse exit variable constant create ' ['] literal ( \ s" ." char
  [char] catch throw words depth bye`.
- Console: z80pack cpmsim TCP console 1, ports 40 (status: bit 0 rx ready,
  bit 1 tx ready) and 41 (data). The kernel echoes input; CR, LF or CR LF end
  a line; backspace edits. After each line it prints ` ok`.

## Layer 4: the Scheme

- One heap object = one 4-byte cell (car, cdr) + a type byte. Pairs, symbols,
  closures, primitives, 32-bit integers, strings (list of char codes),
  vectors (list of elements), macros.
- Mark-sweep GC. Roots: the symbol list plus a conservative scan of the data
  and return stacks.
- Proper tail calls: `eval` is a loop; `if`, `begin`, bodies and closure
  calls continue the loop.
- Special forms in Forth: `quote if define set! lambda begin define-macro`.
  Everything else (`let let* letrec letrec* named let cond => case and or when
  unless do`) is a `define-macro` in `prelude.scm`. An expansion replaces its
  call form in place, so each form expands once.
- `(forth)` returns to the Forth prompt; `lisp` re-enters the REPL.

## Emulator: z80pack cpmsim

Chosen because it is maintained (release 1.39, 2025), MIT licensed, builds
from source with only a C compiler, runs headless, and has a TCP console built
in (`conf/net_server.conf`), so `PORT` works like QEMU's `-serial tcp:`. It
also ships `z80asm`, the reference assembler for the layer 2 tests.
RunCPM needs a CP/M program and stdio only; MAME is large to build on g.

`build-emu.sh` clones z80pack to `~/src/z80pack` (tested at 91fd28e) and builds
it with three edits: the named-pipe auxiliary device is off (it needs a
helper and is shared between instances), a stale constant in that code path
is fixed, and a TCP console peer that disconnects is dropped instead of
stopping the CPU (upstream stops with a fatal I/O error; the Lisp launcher
reconnects after loading).

## Memory map and limits

| Range | Use |
|---|---|
| 0000-0DDC | kernel image (3549 bytes) |
| 0DDD-E7FF | dictionary: lisp.fs, heap, types, symbol names (`here` = B2FA after load, 13.5 KiB free) |
| E800-EBFF | terminal input buffer: 1023 characters per line |
| EC00-F7FF | return stack, 3 KiB (IX starts at F800) |
| F800-FFFF | data stack, 2 KiB (SP starts at 0000) |

- Heap: 7000 cells (28000 bytes) + 7000 type bytes. 5129 cells free after the
  prelude. `(room)` returns the free count after the last GC.
- Integers: 32-bit signed, boxed; overflow wraps. `quotient`, `remainder`,
  `modulo` need a divisor in -32768..32767 (an error otherwise).
- `sqrt` is an integer square root (floor); `floor` is the identity. No
  floats, rationals, characters (a char is its code), or `call/cc`.
- One expression may not span lines; a line holds 1023 characters.
- Vectors and strings are lists inside: `vector-ref` is O(n).
- No arity checks on closures; no stack overflow checks (deep non-tail
  recursion over about 150 levels can overrun the 3 KiB return stack).
- Macros are not hygienic; expansions use the names `%t %c %k %do`.
- Symbols are never collected.

## Running

```
z80-forth             # Forth prompt
z80-lisp              # Forth + lisp.fs + prelude.scm, Scheme REPL
PORT=4500 z80-lisp    # another TCP port for the emulated console
./test.sh             # all three test layers
```

## Tests and measured results (2026-10-04)

| Layer | Test | Result |
|---|---|---|
| 2 assembler | `test-asm.lisp`: every encoding form vs z80pack `z80asm` | 434 passed, 0 failed |
| 3 kernel | `host.lisp test-forth`: kernel words over serial | 45 passed, 0 failed |
| 4 Lisp | `host.lisp test`: `../r7rs-tests.scm` | 205 passed, 0 failed |

`test.sh` runs all three in 41 s. cpmsim runs unthrottled at about 450 MHz
of emulated Z80 clock.

## Conformance file

`r7rs-tests-z80.scm` is the 205-case suite this port was validated against (the shared suite as of
the merge). The shared suite has since grown cases for number, character and blob features
that only the STM32 Scheme has; the Z80 harness has no per-case timeout, so it keeps its pinned copy.
